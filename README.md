# 方寸工具箱 · Fancun Toolkit

> **方寸之间，得心应手。**

一个零依赖、零构建、纯前端的开发者在线工具箱。16 个高频小工具收在同一个页面里，选中即用，不需要注册、不需要安装，输入的内容不会离开浏览器。

**在线体验：[https://tools.v5pc.com](https://tools.v5pc.com)**

## 这是什么

一个零依赖、零构建、纯前端的开发者在线工具箱。16 个高频小工具收在同一个页面里，选中即用，不需要注册、不需要安装，输入的内容不会离开浏览器。

整站前端约 4500 行手写 JavaScript，没有框架、没有打包器、没有 `node_modules`，双击 `index.html` 就能跑，断网也能用。

## 为什么做

日常开发里最消耗耐心的往往是两类小事：

一是为了转个 Base64、算个时间戳，去搜一个页面挂满弹窗、加载三秒、还要点两次"复制"的在线工具；

二是把接口返回、密钥片段、日志贴进不知底细的网站，贴完心里发虚。

这两件事都不该这么麻烦。所以做了方寸：单页、秒开、纯本地运算，用完即走。

## 快速开始

**方式一：直接打开。** 双击 `index.html`。`file://` 协议下 16 个工具功能完整（图片导出、二维码、哈希、JWT 验签都可用），断网也行。

**方式二：本地起个服务**（零依赖，Node ≥ 16）：

```bash
node server.js            # http://localhost:3100
PORT=8080 node server.js  # 换端口
```

或 `npm start`（同上）。这个 `server.js` 只是本地预览与容器场景用的静态服务器，带 gzip，不参与生产。

**方式三：丢进任意静态托管。** 整个仓库就是产物，没有构建步骤。Nginx / OSS / Pages 直接指向根目录即可。

## 技术亮点

- **零依赖、零构建**：没有框架、没有打包器、没有 `node_modules`，源码即产物，改一行刷新就生效。整站前端约 4500 行手写 JavaScript，唯一的第三方文件是内置的二维码编码实现，为了断网也能用。
- **算法自己写**：MD5、SHA-1、SHA-256 是字节级的纯 JavaScript 实现（含 32 位溢出与分组填充），Base64 编解码、Hex、Unicode 转义全部手写，不调库也不依赖 Web Crypto 的兼容性。
- **大数不塌**：进制转换走 `BigInt`，几十位的十进制数转二进制不丢精度，同时展示二进制分组与位信息。
- **图片全程本地**：用 `createImageBitmap` 解码、`Canvas` 缩放、`toBlob` 重新编码，压缩前后体积直接对比，批量处理完可以一键全部下载。
- **单页架构**：hash 路由 + 按需渲染，切换工具不刷新、不重新下载资源；静态资源带版本串，改动后老访客不会拿到「新 HTML + 旧 CSS」。
- **极简后端**：只需要访问统计和广告位管理，就没有引入数据库和框架，写了单文件 Node 服务——内存聚合 + 定期落盘、scrypt 密码哈希、手写 JWT HS256、登录失败限流锁定，数据保留 180 天自动清理。
- **发版可回滚**：发布走「备份 → 解压预检 → 原子切换」，线上始终保留 3 份快照，出问题一条命令退回上一版。

## 隐私与数据

- 16 个工具的计算**全部在浏览器内完成**，输入内容不上传、不落盘。打开 DevTools 的 Network 面板可以自行验证。
- 唯一的出站请求是匿名页面访问统计：页面标识 + 哈希后的访客标识，不记录输入内容，不存原始 IP。
- 不使用 Cookie、不做跨站追踪、没有账号体系。
- 纯本地使用（`file://` 或自托管）时，把 `js/app.js` 里的 `trackPage()` 调用去掉即可完全静默。

### 侧边栏自定义

工具变多以后，可以只保留常用的那些。点右上角的**管理按钮**（滑块图标）进入管理模式。

| 操作 | 说明 |
| --- | --- |
| ↑ / ↓ | 在同一分组内调整顺序，跨分组不生效（分组本身固定） |
| × | 从侧边栏移除，工具本身仍然可用，只是不显示 |
| + | 把已移除的工具加回菜单 |
| 恢复默认 | 清空所有自定义，回到出厂顺序 |
| 完成 / `Esc` | 退出管理模式 |

侧边栏和首页卡片**同步**：隐藏的工具不会出现在首页，顺序也跟随自定义。配置存在 `localStorage` 的 `dt-menu` 键，纯本地，不上传，换浏览器不跟随。

**这些图不是外部素材，全部由 `brand/` 下的 HTML 用无头 Chrome 按像素渲染生成**，改文案或配色后重跑即可，不依赖任何设计软件：

```bash
CH="/c/Program Files/Google/Chrome/Application/chrome.exe"
"$CH" --headless=new --disable-gpu --hide-scrollbars --window-size=1200,630 --screenshot=og-cover.png "file://$PWD/brand/og-cover.html"
"$CH" --headless=new --disable-gpu --hide-scrollbars --default-background-color=00000000 --window-size=32,32 --screenshot=favicon-32.png "file://$PWD/brand/icon-32.html"
"$CH" --headless=new --disable-gpu --hide-scrollbars --window-size=180,180 --screenshot=apple-touch-icon.png "file://$PWD/brand/icon-180.html"
```

`--default-background-color=00000000` 只给 favicon 用（保留透明圆角）；苹果图标必须不透明，去掉该参数。macOS / Linux 把 `CH` 换成 `google-chrome` 或 `chromium` 即可。

## 部署

纯静态站，任意静态托管都能跑。线上用的是「白名单打包 → 上传 → 解压到新目录 → `test -s` 预检 → 原子切换 → `chown`」这一套，好处是切换瞬间完成、出错直接退回上一版，线上保留最近 3 份快照。

两条实践要点：

- **静态资源带版本串**（`css/style.css?v=20261101j`）。服务端常给 `max-age` 缓存，文件名又不含哈希，改了 CSS 却不改引用地址，老访客会拿到「新 HTML + 旧 CSS」，菜单点了没反应。改前端资源时同步递增 `index.html` 里的 `?v=`。
- **前端构建产物就是源码**，没有 `dist/`。发版清单是白名单，不是黑名单——新增顶层文件要记得加进去，漏了会 404。

> `deploy/` 是早期的部署脚本与 Nginx 配置样例（监听 3100 的旧方案），已废弃，仅作参考，**不要直接执行**。

Chrome / Edge / Firefox / Safari 现代版本。图片导出 WEBP 依赖浏览器支持（已做降级检测）。

## 关于后端

站点本体是纯静态的。访问统计与广告位需要服务端，但只需两件事，所以没有引入数据库和框架，写了 `server/server.js`——单文件、零依赖、Node 原生 `http` + `crypto`：

- PV / UV：内存聚合，8 秒 flush 到 JSON，`SIGINT` / `SIGTERM` 时强制落盘。
- 账号：scrypt 密码哈希，手写 JWT HS256（7 天），登录失败 6 次锁 15 分钟。
- 广告：`/api/ads` 只返回启用且在投放期内的；后台增删改查全走 JWT 鉴权。
- 只监听 `127.0.0.1`，由前置 Nginx 反代，不直接暴露公网。

不想用统计和广告？不用部署后端，静态文件拷走即可，前端的埋点与广告请求都是静默失败，不影响任何功能。

## 已知限制

当前用 hash 路由（`/#json`、`/#jwt`），`#` 之后的内容不会发送给服务器，搜索引擎无法把它当作独立页面。因此 16 个工具只能作为首页的一部分被收录，**拿不到「Base64 在线解码」这类长尾词**。

要让每个工具独立被搜到，需要改成 History API 路由并为每个工具生成预渲染落地页（`/json/index.html` 等），这会改变现有分享链接，尚未实施。
